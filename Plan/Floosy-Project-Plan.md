# خطة مشروع Floosy — إدارة الفلوس والمصاريف الشخصية

> **ملاحظة لأي Developer هيشتغل على المشروع:** المستند ده كامل ومفصّل، لو اتنفذ زي ما هو مكتوب مش محتاج ترجع تسأل صاحب المشروع في حاجة. كل قرار اتاخد وموجود سببه.

---

## 1. فكرة المشروع (Overview)

**الاسم:** Floosy
**النوع:** Web App (موقع ويب، Responsive يشتغل كويس على الموبايل والتابلت والديسكتوب)
**المستخدم:** شخص واحد بس (صاحب المشروع) — مفيش حاجة اسمها تسجيل مستخدمين جداد أو Multi-tenant. يعني حساب واحد محمي بـ Login.

**المشكلة اللي بيحلها:**
المستخدم بيحتفظ بفلوسه في أكتر من مكان (كاش في الجيب، محفظة InstaPay، درج في البيت، أو فلوس عند صاحب) وعايز:
- يعرف هو معاه/عنده فلوس فين بالظبط وكل مكان فيه قد إيه.
- يسجل كل عملية صرف: صرفها فين، إمتى، من أنهي "مكان/محفظة".
- يسجل كل دخل: جاله منين، وقع في أنهي محفظة.
- يتابع الديون: فلوس ليه عند ناس (Lending) وفلوس عليه لناس (Borrowing)، مع تاريخ الاستحقاق.
- يشوف تقرير أسبوعي/شهري/يومي يوضح صرف إيه وفين راحت الفلوس.

## 2. المفاهيم الأساسية اللي البرنامج مبني عليها

### 2.1 المحافظ (Wallets)
كل "مكان" بيحتفظ فيه المستخدم بفلوسه هو **Wallet** مستقل برصيد خاص بيه. مثال:
- كاش (Cash)
- InstaPay
- الدرج (Drawer)
- محفظة صاحبي (فلوس مودعاها عند حد كأمانة)

المستخدم يقدر يضيف/يعدل/يمسح محافظ بنفسه من الإعدادات (مش Hardcoded).

### 2.2 المعاملات (Transactions)
كل حركة فلوس هي Transaction ليها نوع:
- **Expense (مصروف):** بتتخصم من محفظة معينة، وليها تصنيف (Category) زي أكل، مواصلات، فواتير...
- **Income (دخل):** بتتضاف لمحفظة معينة، وليها مصدر (Source) زي مرتب، هدية، تحصيل دين...
- **Transfer (تحويل بين محافظ):** مثلاً حوّل من InstaPay للكاش — بتتخصم من محفظة وتتضاف لمحفظة تانية بنفس القيمة.

### 2.3 الديون (Debts)
نوعين:
- **لي فلوس عند حد (Lent):** أنا اديت حد فلوس، لازم ترجعلي. بتتسجل: المبلغ، لمين، تاريخ الإدانة، تاريخ الاستحقاق المتوقع (اختياري)، حالة (مستحقة/متأخرة/مسددة).
- **عليا فلوس لحد (Borrowed):** أنا مديون لحد بفلوس. نفس البيانات لكن بالعكس.

لما دين يتسدد (كليًا أو جزئيًا) بيتسجل كـ Transaction (Income لو هو حصّل، أو Expense لو هو سدد) ومرتبط بالـ Debt نفسه، عشان الرصيد يتحدث صح والتاريخ يفضل موثق.

### 2.4 التصنيفات (Categories)
قائمة تصنيفات جاهزة (Default) + إمكانية إضافة تصنيف جديد:
أكل ومشروبات، مواصلات، فواتير، صحة، تسوق، ترفيه، تعليم، إيجار، اشتراكات، تحويلات لناس، متفرقات.

## 3. المميزات (Features) بالتفصيل

1. **تسجيل دخول بسيط** — Email/Password واحد بس (صاحب الموقع)، عن طريق Firebase Authentication.
2. **Dashboard رئيسية:**
   - إجمالي الفلوس عندك (مجموع كل المحافظ).
   - كارت لكل محفظة برصيدها.
   - إجمالي "ليا" و"عليا" من الديون.
   - Chart بسيط لصرف آخر 7 أيام.
   - آخر 5 عمليات.
3. **شاشة المحافظ (Wallets):** عرض/إضافة/تعديل/حذف محفظة، وتفاصيل كل محفظة (كل العمليات اللي حصلت فيها).
4. **إضافة عملية جديدة (Add Transaction):** فورم سريع — نوع العملية (صرف/دخل/تحويل)، المبلغ، المحفظة، التصنيف، تاريخ، ملاحظة اختيارية.
5. **شاشة العمليات (Transactions List):** كل العمليات بترتيب زمني، مع فلاتر (بالمحفظة، بالتصنيف، بالتاريخ من/لـ، بحث نصي في الملاحظات).
6. **شاشة الديون (Debts):** تبويبين "ليا" و"عليا"، كل عنصر فيه الاسم، المبلغ المتبقي، تاريخ الاستحقاق، وزرار "سدد/حصّل" (كلي أو جزئي).
7. **التقارير (Reports):**
   - Toggle بين يومي/أسبوعي/شهري.
   - Chart دائري (Pie) لتوزيع الصرف حسب التصنيف.
   - Chart عمودي (Bar) للصرف عبر الوقت.
   - مقارنة الدخل بالمصروف في نفس الفترة.
8. **الإعدادات (Settings):** إدارة المحافظ، إدارة التصنيفات، تغيير كلمة السر، Dark/Light mode.
9. **تنبيه بصري** للديون اللي قربت أو فاتت على تاريخ استحقاقها (Badge أحمر في الـ Dashboard وصفحة الديون).

## 4. هيكلة قاعدة البيانات (Firestore)

```
users/{uid}
  displayName, email, createdAt

wallets/{walletId}
  ownerId, name, icon, color, balance, createdAt

transactions/{transactionId}
  ownerId, type: "expense" | "income" | "transfer"
  amount, date, note
  walletId            // للمصروف والدخل
  fromWalletId, toWalletId   // للتحويل بس
  categoryId          // للمصروف
  source              // للدخل (نص حر: مرتب، هدية...)
  relatedDebtId        // لو العملية دي تسديد/تحصيل دين

debts/{debtId}
  ownerId, direction: "lent" | "borrowed"
  personName, totalAmount, remainingAmount
  createdAt, dueDate (اختياري)
  status: "open" | "partially_paid" | "settled"
  note

categories/{categoryId}
  ownerId, name, icon, color, type: "expense" | "income"
```

**قواعد الأمان (Firestore Rules):** كل الـ Collections مقفولة بـ `request.auth.uid == resource.data.ownerId`، ومفيش حد يقدر يقرا أو يكتب غير صاحب الحساب.

## 5. التكنولوجيا (Tech Stack) — القرار النهائي

| الطبقة | التقنية | السبب |
|---|---|---|
| Frontend | React (Vite) + TypeScript | بناء سريع، Type-safety، سهل الصيانة |
| Styling | Tailwind CSS | نفس نظام التصميم اللي هنطلعه من Stitch |
| Charts | Recharts | خفيف وسهل التكامل مع React |
| Backend/DB | Firebase (Firestore) | مفيش حاجة اسمها Server منفصل، مناسب لمشروع شخصي، Real-time out of the box |
| Auth | Firebase Authentication (Email/Password) | حساب واحد، سريع الإعداد |
| Hosting | Firebase Hosting | Deploy بأمر واحد، Free tier كفاية للاستخدام الشخصي |
| Cloud Functions (اختياري) | Firebase Functions | لو احتجنا نحسب تقارير معقدة أو نبعت تنبيهات لاحقًا |

> Node.js/Express مش هيتم استخدامه كـ Backend منفصل لأن Firestore + Security Rules بتغني عنه في مشروع بالحجم ده؛ ده بيقلل التعقيد ومصاريف السيرفر. لو حبيت تضيف Backend مخصص لاحقًا (Node.js + Express) هيبقى سهل لأن الـ Data model جاهز.

## 6. خريطة الشاشات (Pages)

1. `/login` — تسجيل الدخول
2. `/` — Dashboard
3. `/wallets` — قائمة المحافظ
4. `/wallets/:id` — تفاصيل محفظة
5. `/transactions` — كل العمليات + فلاتر
6. `/transactions/new` — إضافة عملية (ممكن تبقى Modal بدل صفحة منفصلة)
7. `/debts` — الديون (تبويب ليا/عليا)
8. `/reports` — التقارير
9. `/settings` — الإعدادات

## 7. خطة التنفيذ (Sprints)

**Sprint 1 — الأساس:**
Setup للمشروع (Vite + React + TS + Tailwind)، ربط Firebase (Auth + Firestore)، شاشة Login، الـ Routing العام، الـ Layout الرئيسي (Sidebar/Bottom nav للموبايل).

**Sprint 2 — المحافظ والعمليات:**
CRUD كامل للمحافظ، فورم إضافة عملية (صرف/دخل/تحويل)، شاشة قائمة العمليات مع الفلاتر، تحديث رصيد المحفظة تلقائي عند كل عملية (Firestore Transaction عشان الاتساق).

**Sprint 3 — الديون:**
CRUD للديون، منطق التسديد الجزئي/الكلي وربطه بالـ Transactions.

**Sprint 4 — Dashboard والتقارير:**
بناء الـ Charts، حسابات التجميع (يومي/أسبوعي/شهري)، الـ Dashboard الرئيسية.

**Sprint 5 — التلميع:**
Dark mode، تنبيهات الديون المستحقة، تحسين الأداء على الموبايل، اختبار شامل، Deploy على Firebase Hosting.

## 9. ملاحظات تنفيذية مهمة للـ Developer

- **الاتساق المالي:** أي تحديث لرصيد محفظة لازم يتم داخل Firestore Transaction/Batch Write مع إنشاء الـ Transaction record، عشان منوصلش لحالة إن الرصيد اتحدث والـ Log لأ (أو العكس).
- **التحويل بين محافظ** لازم يخصم من محفظة ويضيف لمحفظة تانية في نفس الـ Batch.
- **تسديد الدين الجزئي** يقلل `remainingAmount` وينشئ Transaction مرتبطة، ولو `remainingAmount` وصل صفر يتغير `status` لـ `settled` تلقائيًا.
- **الأرقام:** استخدم وحدة أصغر (قروش/سنتات) في التخزين لتفادي مشاكل الفاصلة العشرية، أو استخدم مكتبة زي `decimal.js` لو خزّنت بالجنيه مباشرة.
- **التاريخ:** خزّن كـ Firestore Timestamp، واعرض بتنسيق عربي مناسب.
